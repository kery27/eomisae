# 어미새 시제품 (1.5단계)

> `docs/개발-계획.md` 2장 1.5단계. **화면은 대충, 목적은 "된다/안 된다" 확인.**
> 이 앱으로 확인한 결과를 보고, 각 기능을 Flutter 플러그인으로 갈지 Kotlin으로 직접 쓸지 정한다.

## 확인할 네 가지

| # | 확인 | 이 앱에서 보는 곳 |
|---|---|---|
| 1 | 앱을 닫고 화면을 꺼도 타이머 서비스가 30분 넘게 살아 있는가 | 결과 → **서비스 멈춤** 목록(5초 넘게 박동이 끊긴 구간) |
| 2 | 앱이 꺼져 있어도 알림창 [픽업]이 기록되는가 | 결과 → 대기 기록의 `via: notification` |
| 3 | 유튜브 위 떠 있는 타이머에서 누른 [픽업]이 기록되고, 알림창·앱 화면에도 반영되는가 | 결과 → `via: overlay`, `처리 지연 N초` |
| 4 | 실제 배달 중에 오토바이 이동과 정차가 구분되는가 | 결과 → **활동 변화** 목록(IN_VEHICLE / STILL / ON_BICYCLE …) |

## 구조

```
lib/
  main.dart        앱 화면(권한, 대기 시작, 활동 인식, 결과) + 오버레이 진입점(overlayMain)
  timer_task.dart  포그라운드 서비스 안에서 1초마다 도는 타이머
  overlay.dart     다른 앱 위에 떠 있는 타이머(별도 Flutter 엔진)
  wait_store.dart  세 곳이 함께 보는 대기 상태와 기록
```

**상태 공유 원칙 (개발-계획 1-2):** 대기 상태의 원본은 `wait_store.dart`의 저장소 하나다. 대기를 **끝내는 것(픽업·취소 적용)은 타이머 서비스만** 한다. 앱 화면과 떠 있는 창은 "픽업해 주세요"라는 요청만 남기고, 서비스가 1초마다 읽어서 처리한다. 그래서 떠 있는 창에서 누른 [픽업]도 서비스를 거쳐 알림창과 앱 화면에 똑같이 반영된다.

서비스가 1초마다 "박동" 시각을 남기고, 박동이 5초 넘게 끊기면 **서비스 멈춤**으로 기록한다. 갤럭시 절전 기능이 서비스를 재우는지 확인하는 용도다.

## 사용한 플러그인

| 기능 | 플러그인 | 버전 | 최근 업데이트 | 메모 |
|---|---|---|---|---|
| 포그라운드 서비스 타이머, 알림 버튼 | `flutter_foreground_task` | 11.0.3 | 2026-09 | 활발히 관리됨 |
| 떠 있는 타이머 | `system_alert_window` | 2.0.11 | 2026-05 | `flutter_overlay_window`(2025-04 이후 업데이트 없음) 대신 선택 |
| 활동 인식 | `activity_recognition_flutter` | 6.1.0 | 2026-08 | `flutter_activity_recognition`(2024-09 이후 없음) 대신 선택 |
| 권한 | `permission_handler` | 13.0.2 | 2026-09 | |

**알아둘 점**
- `activity_recognition_flutter`는 **앱이 살아 있는 동안만** 동작한다(자체 포그라운드 서비스로 백그라운드는 유지). 설정에서 앱을 강제 종료하면 멈춘다.
- 이 플러그인은 자체 포그라운드 서비스를 `health` 종류로 띄운다. 정식 앱에서는 Play 심사에서 용도 설명이 필요할 수 있다.
- 타이머 서비스는 `specialUse` 종류로 선언했다(AndroidManifest의 설명 문구 포함). 정식 출시 때 Play 심사에서 설명을 요구한다.

## 빌드하고 폰에 설치하기

필요한 것: Flutter 3.44 이상(개발 때 3.47.5 사용), Android Studio(안드로이드 SDK), 갤럭시 폰(개발자 옵션 → USB 디버깅 켜기).

```bash
cd prototype
flutter pub get
flutter run            # USB로 연결한 폰에 바로 설치·실행
# 또는
flutter build apk --debug   # build/app/outputs/flutter-apk/app-debug.apk 를 폰에 옮겨 설치
```

> 이 저장소를 만든 환경에서는 안드로이드 SDK를 받을 수 없어서 **APK 빌드는 해보지 못했다.** `flutter analyze`(문제 없음)와 `flutter test`(통과)만 확인했다. 빌드 중 Gradle·Kotlin 버전 오류가 나면 오류 메시지를 그대로 공유하면 된다.

## 테스트 순서

**준비 (처음 한 번)**
1. 앱을 열고 **1. 권한**의 네 가지를 모두 [허용하기]. 특히 "배터리 최적화 제외"는 1번 확인에 중요하다.

**확인 1·2: 서비스 생존과 알림창 버튼**
1. [대기 시작] → 알림창에 "○○ 대기 0분"과 [픽업]·[취소]가 뜨는지 본다.
2. **최근 앱 목록에서 앱을 밀어서 닫는다.** 화면을 끄고 30분 이상 둔다(실제 대기 때 해보면 가장 좋다).
3. 알림창에서 분이 올라가는지 확인하고, 알림창 [픽업]을 누른다.
4. 앱을 다시 열어 **4. 결과**: 대기 기록에 `notification`으로 남았는지, **서비스 멈춤**이 있는지 본다.

**확인 3: 떠 있는 타이머**
1. [대기 시작] → 화면 위쪽에 "대기 0분" 알약이 뜬다. 유튜브를 켠다.
2. 알약을 끌어서 옮겨 보고, 눌러서 펼친 뒤 [픽업].
3. "요청 보냄" → 1~2초 안에 "기록됨"으로 바뀌고 창이 닫히는지, 알림창도 사라지는지 본다.
4. 결과에서 `overlay`와 처리 지연 시간을 본다.

**확인 4: 활동 인식**
1. **3. 활동 인식**의 [기록 시작]을 누르고 평소처럼 배달한다(한두 시간).
2. 결과의 활동 변화 목록에서, 오토바이로 달릴 때 `IN_VEHICLE`(또는 `ON_BICYCLE`)이, 가게 앞에서 멈췄을 때 `STILL`이 제때 찍히는지 본다. 바뀌는 데 몇 초·몇 분 걸리는지도 적는다.

**결과 공유:** 결과의 [전체 복사]를 누르면 기록이 JSON으로 복사된다. 그대로 붙여넣어 공유하면 된다.

## 결과 기록표

| 확인 | 결과 (된다 / 안 된다 / 부분) | 메모 (폰 기종, 안드로이드 버전, 이상했던 점) |
|---|---|---|
| 1. 서비스 30분 생존 | | 서비스 멈춤 건수: |
| 2. 앱 꺼진 상태에서 알림창 [픽업] | | |
| 3. 떠 있는 타이머 [픽업] 반영 | | 처리 지연: 초 |
| 4. 이동/정차 구분 | | 정차 → STILL까지 걸린 시간: |

**판단**
- 모두 "된다" → 이 플러그인 조합으로 2단계 진행.
- 1·2가 안 되면 → 절전 예외 안내를 먼저 시도, 그래도 안 되면 타이머 서비스를 Kotlin으로 직접 작성.
- 3이 안 되면 → 오버레이만 Kotlin(WindowManager)으로 작성.
- 4가 부정확하면 → 미니 현황의 "이동 중 숨김"을 확인 알림 방식으로 바꾸는 것 검토(H6).
